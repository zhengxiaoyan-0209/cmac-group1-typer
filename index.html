What this page does

The published workflow aligns each genome against the reference and reads the alleles at 85 Group 1–specific positions. This page reproduces that decision in the browser using an anchoring strategy instead of a full alignment, which returns a result in seconds.

  1. Take the 25 bp immediately next to a SNP as an anchor;
  2. Locate that anchor in the query assembly and in its reverse complement;
  3. Once anchored, read the single adjacent base — that is the observed allele;
  4. If the 25 bp anchor is absent, fall back to 20 bp and then 16 bp;
  5. If the anchor matches several places and different bases are read, the locus is scored “undetermined” — a missed call is preferable to a wrong one.

Why two versions of each flank are stored

The 85 loci are not evenly spaced; the densest cluster holds six positions inside one 25 bp window (around 2,390 kb). Taking the flank from the reference alone would make the anchor cover a neighbouring mutation, and genuine Group 1 strains would fail to anchor at all. Each flank is therefore also stored in a “Group 1 haplotype” version, and both are searched, so neither allele is favoured.

How to read the result

  • Match score = loci carrying the Group 1 allele ÷ loci where a call could be made.
  • No conclusion is reported when fewer loci than “minimum coverage” can be read, since the evidence is then insufficient.
  • Score ≥ upper threshold → Group 1; ≤ lower threshold → not Group 1; in between → inconclusive (worth a closer look for recombination or a chimeric assembly).

Known limits

  • The input must be an assembled genome (a draft split into contigs is fine); raw reads are not supported.
  • A locus whose flank runs off the end of a contig, or carries another variant within 16 bp, cannot be scored and is counted as undetermined; the other loci are unaffected.
  • This page is an approximation of the alignment workflow. Results intended for publication should still be produced with bwa / snippy + snp-sites as described in the paper.
